# GSC 请求索引

## 做什么

1. GSC →「网址检查」输入目标 URL。
2. 先点「**测试实际网址**」，确认实时抓取通过。
3. 测试通过后点「**请求编入索引**」。

## 合格标准

- 先测试、后请求，顺序不颠倒。
- 配额优先给：首页、核心栏目页、高价值新内容页。

## 常见坑

- **配额约 10–15 个/天**，浪费在低价值页（标签页、分页、测试页）上。
- 不测试实际网址直接请求——如果页面有实时问题，请求直接失败还占配额。
- 对同一 URL 反复请求，无叠加效果。
- 以为请求 = 保证收录：它只是加速抓取，内容不够格照样不索引（→ google-content-value）。

## 适用优先级

1. 新发布的高价值内容
2. 修复 P0 问题后的重新提交
3. 重要的改版页面
